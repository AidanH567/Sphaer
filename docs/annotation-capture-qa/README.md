# Annotation capture — does the screenshot survive the flatten?

Generated by `npx tsx scripts/qa-annotation-capture-fidelity.ts`. Regenerate after touching
`AnnotationCanvas`, `annotation.ts`, or `annotation-capture.ts`.

## The bug

Report `97398534`: *"when you draw on a screenshot… the photo is blank and you can only
see what users draw on a blank page."*

`Svg.toDataURL()` on web serialises the SVG and rasterises it through an `<img>`, which
the browser renders in **secure static mode** — no external resource may be loaded.
`expo-image-picker` on web returns a `blob:` URI, so the image resolved to nothing and the
capture came out as strokes over a void. The preview looked fine throughout, because the
live DOM has no such restriction — which is why `onLoad` fired and the old
`imageReady` guard never triggered.

## Result

| | BEFORE (`blob:`) | AFTER (`data:`) |
| --- | --- | --- |
| Valid PNG, correct size | yes — 390×844 | yes — 390×844 |
| File size | 6095 B | 13612 B |
| Screenshot cells retained | 68/1024 (6.6%) | 1024/1024 (100.0%) |
| `assertCaptureFidelity` (min 90%) | **refused** | **accepted** |

Both files are valid PNGs of exactly the right dimensions. That is the whole problem with
checking files instead of pixels — the BEFORE column passes every structural test there is.

The message the reporter now gets instead of a blank report:

> Your marks saved but the screenshot behind them didn't, so the report would have shown drawings on a blank page. Nothing was sent — please try attaching the screenshot again.

For reference, the BEFORE capture's mean colour over the whole frame is rgb(2, 0, 0) at alpha 1.1/255 — an empty canvas with a little ink on it.

## Are the screenshot’s own pixels there?

Alpha presence alone would accept any opaque rectangle. Each block of the source is
therefore compared to the same band of the capture, by colour:

| Block | Source | Capture (mean) | Max drift | |
| --- | --- | --- | --- | --- |
| header | #1B1B18 | rgb(27, 27, 24) | 0.0 | present |
| body | #FCFCF9 | rgb(252, 252, 249) | 0.0 | present |
| card | #E4572E | rgb(229, 86, 46) | 1.2 | present |
| footer | #2E5E4E | rgb(46, 94, 78) | 0.0 | present |

Every block survives the flatten at its own colour. The marker circle accounts for the
few units of drift where it crosses a band.

## Limitation

Rasterised by sharp/librsvg, which enforces the same no-external-resources rule as a
browser rasterising an SVG in an `<img>`. This demonstrates the mechanism and the guard’s
verdict flipping between the two href forms; it is not a capture taken from Safari on a
phone.
